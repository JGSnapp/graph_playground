# Система расстановки артефактов — снимок v1.0

Зафиксированное состояние на момент начала работ по улучшению.
Всё, что описано ниже, реально существует в коде. Изменения фиксируются
в [EXPERIMENTS.md](EXPERIMENTS.md), критерии качества — в [QUALITY_MODEL.md](QUALITY_MODEL.md).

---

## 1. Архитектура

```
shared/     чистая геометрия и метрики: без React, без express, без сети
  geometry.ts       порты, углы подхода, ортогональные полилинии, bbox
  routing.ts        A* по сетке Ханана, автомаршрутизация, очистка изгибов
  intersections.ts  детектор 10 типов дефектов раскладки
  quality.ts        веса, cost, score, подсказки
  placement.ts      сравнение вариантов положения блока
server/     express + SSE, файловые JSON-хранилища, агентный цикл
  modules/agent     цикл агента, тулы, промпт, чекпоинты, лог прогонов
  modules/boards    состояние досок, undo/redo, операции
  modules/llm       OpenAI-совместимый клиент (DS Lab)
  modules/knowledge векторная БД + эмбеддинги
  modules/skills    редактируемый каталог инструкций
web/        React-канвас, SSE-чат, панели настроек
bench/      стенд экспериментов (добавлен в рамках этих работ)
```

Ключевое свойство: **вся математика раскладки живёт в `shared/` и одинаково
доступна серверу, клиенту и бенчу**. Метрика качества — одна на всех.

## 2. Инструменты агента (22 штуки)

### 2.1. Скиллы

| Тул | Что делает |
|---|---|
| `skill_list` | каталог: slug, имя, когда применять |
| `skill_get(slug)` | полный текст инструкции |

Каталог скиллов подставляется в системный промпт всегда; тела — по запросу.
Скиллы редактируются из UI и хранятся в `data/skills.json`.
Отключаются целиком флагом `settings.skills.enabled`.

### 2.2. Восприятие доски

| Тул | Что возвращает |
|---|---|
| `board_get_region(x,y,w,h)` | точные данные: id, тип, координаты, размеры, props артефактов и стрелок |
| `board_get_schema(..., format)` | ASCII-план 68×30 символов или SVG-схема области |
| `board_screenshot(...)` | настоящие пиксели от подключённого клиента; при таймауте 12с — ASCII-фолбэк |
| `board_check_intersections(...)` | полный отчёт детектора + `quality` + `improvedBy` + `verdict` |

Без аргументов область = bbox всего содержимого + 120px.

### 2.3. Артефакты

| Тул | Особенности |
|---|---|
| `artifact_create(type,x,y,...)` | **отказывается** при наложении, пока не передан `acceptOverlap=true` |
| `artifact_update(id,...)` | props по умолчанию сливаются; тот же гейт на наложение |
| `artifact_move(id,x,y)` | тот же гейт; сообщает, сколько маршрутов сброшено |
| `artifact_delete(id)` | удаляет вместе с присоединёнными стрелками |
| `artifact_rank_placements(id, placements[])` | **доску не меняет**: прогоняет до 8 вариантов положения через роутер и `boardQuality`, возвращает ранжирование |

Типы артефактов и дефолтная геометрия (`artifact.defaults.ts`):
`note` 240×180, `text` 320×64, `shape` 200×140, `image` 320×240,
`website` 480×360, `console` 460×260, `code` 440×280.

### 2.4. Стрелки

| Тул | Особенности |
|---|---|
| `arrow_create(fromId,toId,...)` | стороны явные или `auto`; **два гейта**: плоский подход (<30°) и смешанный порт (<48px) |
| `arrow_update(id,...)` | те же гейты |
| `arrow_bend_add / _move / _remove` | ручные изгибы |
| `arrow_delete(id)` | — |

`fromOffset`/`toOffset` (0..1 вдоль стороны) намеренно необязательны: без них
доска сама разводит порты, чтобы параллельные линии не сливались.

### 2.5. Раскладка

| Тул | Особенности |
|---|---|
| `board_route_arrows(...)` | A* по сетке Ханана; **отказывается целиком**, если есть наложения блоков или порт внутри соседа; предупреждает про «крюки» (`detourRatio > 1.8`) |
| `board_clean_arrows(...)` | выпрямляет полилинии, убирает мёртвые точки сгиба; нового маршрута не ищет |
| `board_quality(note?)` | score/cost/grade + разбор по причинам + сравнение с прошлым замером |

### 2.6. База знаний

| Тул | Особенности |
|---|---|
| `kb_search(query, topK)` | семантический поиск по локальной векторной БД |
| `kb_add(...)` | доступен, только если `settings.knowledge.writeEnabled` |

Оба скрываются из списка тулов, если чтение отключено — механизм `isEnabled(settings)`
в `ToolSpec` позволяет выключать любой инструмент настройками, без правки кода.

## 3. Политики (что система запрещает и как настаивает)

### 3.1. Жёсткие гейты — действие отменяется

1. **Наложение артефактов.** `artifact_create/update/move` отказываются, пока
   агент не подтвердит `acceptOverlap=true`.
2. **Плоский подход стрелки.** Угол к стороне < 30° → `arrow_create/update`
   отказываются, просят добавить изгиб.
3. **Смешанный порт.** Вход и выход на одном блоке ближе 48px → отказ
   с предложением конкретного `offset` или другой стороны.
4. **Тесная раскладка.** `board_route_arrows` при наложениях блоков или порте
   внутри соседа **не пишет ни одного маршрута** и требует раздвинуть узлы.

### 3.2. Мягкие политики — предупреждения в ответе тула

- Предупреждение о «крюке» с объяснением вероятной причины (неверные стороны
  или теснота).
- `verdict` в `board_check_intersections`: «стало лучше на N», «лучше не стало,
  сделай то-то».
- `hints` из `boardQuality`: адресные советы под каждый тип нарушения.

### 3.3. Политика прогона (`agent.service.ts`)

- Лимит итераций: `settings.agent.maxIterations` (в проде сейчас 50),
  либо «безлимит» с защитным потолком 500.
- Результат каждого мутирующего тула отправляется чекпоинтом. Критерий «лучший»:
  **больше артефактов → больше стрелок → меньше cost**.
- При исчерпании лимита доска **откатывается на лучший чекпоинт**, а не
  остаётся в полуразобранном виде.
- Каждый прогон пишется в `data/runs.json` со всеми вызовами, отказами
  и парой quality до/после — это готовая телеметрия для анализа.
- История чата подаётся модели в виде плоского текста; висячих `tool_call`
  без результата провайдер не видит.

## 4. Системный промпт (v1.0)

Живёт в `server/src/modules/settings/defaults.ts` (`DEFAULT_SYSTEM_PROMPT`),
редактируется из UI и хранится в `data/settings.json`.

Структура:
1. Роль: «движок расстановки артефактов на бесконечной доске».
2. Система координат: x вправо, y вниз, пиксели мира.
3. Раздел «Как работать» — 10 пунктов: сначала посмотри доску, обязательно
   прочитай скилл, шаг сетки 20px, фигуры групп (две колонки / треугольник / 2×2),
   встречные стороны, изгибы только через роутер, что делать при отказе роутера.
4. Раздел «Законы раскладки» — действуют в любом скилле. Главный тезис:
   **расстояние на доске должно читаться как расстояние по смыслу**.

Промпт склеивается с четырьмя блоками контекста (`prompt.ts`):
каталог скиллов → текущее состояние доски (до 40 артефактов + оценка качества)
→ статус базы знаний.

## 5. Скиллы (v1.0)

Два штатных, оба в `server/src/modules/skills/seed.ts`:

| slug | Когда | Суть |
|---|---|---|
| `artifact-set` | показать материал: список, карточки, подборка | сетка 20px, форма по количеству (ряд / 3-4 колонки / колонки по группам), 40px воздуха, не строить граф там, где просили список |
| `graph-layout` | связная структура: схема, дерево, пайплайн, вики | 6 шагов: описать граф словами → сгруппировать по смыслу → соединить → **один** вызов роутера → цикл проверок → ответ |

Ключевые правила `graph-layout`:
- внутри группы 100–140px, между группами от 300px;
- лист обязан стоять ближе к своему корню, чем к чужому узлу;
- фигура групп: 2 → две колонки, 3 → треугольник или Г, 4 → квадрат 2×2;
  одна колонка допустима только для конвейера;
- перед сдвигом связанного узла — обязательный `artifact_rank_placements`;
- роутер вызывается один раз, после того как все перестановки закончены;
- останов: `ok=true`, либо два прохода без улучшения, либо 6 проходов.

## 7. Известные ограничения v1.0

Подробный разбор — в [QUALITY_MODEL.md §7](QUALITY_MODEL.md). Кратко:

1. **Нет метрики расстановки узлов.** Оценивается только результат прокладки
   стрелок. Требования про смысловую близость, группы и фигуры живут
   исключительно в тексте промпта и ничем не проверяются.
2. **Гейты дороги для слабых моделей.** Первый же замер показал прогон,
   где больше 10 итераций подряд ушло на борьбу с отказами `arrow_create`.
3. **`ok` требует нуля пересечений стрелок.** Для плотных графов это
   недостижимо и провоцирует бесконечные правки.
4. **Нет понятия «занятая зона» и «свободное место»** — только сырой список
   артефактов в области.
5. **Нет группового примитива.** Подграфы существуют только в голове модели;
   нельзя двигать или размечать группу как целое.
6. **Провайдер:** до правки в рамках этих работ вся линейка Claude 5 и `kimi-k3`
   получали 400 из-за отправки `temperature`. Исправлено списком + одной
   слепой ретрай-попыткой без sampling-параметров.

## 8. Стенд экспериментов `bench/`

Добавлен, чтобы улучшения можно было мерить, а не обсуждать.

| Файл | Назначение |
|---|---|
| `bench/tasks.ts` | фиксированный пул из 8 задач (граф, конвейер, дерево, состояния, карточки, дополнение готового, соседство с занятой зоной, стресс на 14 узлов) |
| `bench/run.ts` | гоняет задачу на модели через живой сервер, отвечает на запросы скриншотов настоящим PNG, пишет JSON + PNG результата |
| `bench/render.ts` | board → SVG → PNG (resvg), визуально соответствует канвасу |
| `bench/metrics.ts` | наблюдательные метрики, которых нет в движке: fidelity соседства, пропорции, разброс длин рёбер, выравнивание |
| `bench/report.ts` | сводные markdown-таблицы по экспериментам и моделям |

Запуск:

```bash
# сервер стенда на отдельной data-директории
TECA_DATA_DIR=./bench/data PORT=5199 node_modules/.bin/tsx server/src/index.ts

# прогон
node_modules/.bin/tsx bench/run.ts --exp=E01 --task=all \
  --model=claude-sonnet-5,gpt-5.6-terra,deepseek-v4-flash --concurrency=6

# отчёт
node_modules/.bin/tsx bench/report.ts --exp=E01,E02
```
