# teca — платформа для гипотез о движке расстановки артефактов на LLM

Платформа для планомерной разработки, внедрения и тестирования гипотез по созданию движка
расстановки артефактов на основе LLM. Агент видит бесконечную доску, рассуждает о композиции и
раскладывает на ней артефакты своими инструментами — а вы наблюдаете каждый его шаг в чате,
меняете модель, промпт и базу знаний и сравниваете результаты.

## Устройство системы

Система делится на несколько блоков.

### 1. Чат с агентами (справа)

В чате отображаются как сообщения агента, так и тулы, которые он вызывает, и остальное:
аргументы и результат каждого вызова раскрываются по клику, у ошибок видно текст ошибки, у
reasoning-моделей — отдельный блок рассуждений. Можно прикреплять вложения: изображения (уходят
в модель как vision-контент), текстовые файлы, drag-and-drop и вставка из буфера. Ответ приходит
потоком, run можно остановить кнопкой «Стоп». Панель чата тянется за разделитель. Текст сообщений
рендерится как markdown (заголовки, списки, таблицы, инлайн-код и блоки кода).

### 2. Блок досок (всё пространство левее чата)

На нём отображаются доски, с которыми работают агенты. Есть кнопка «Новая доска». При нажатии на
доску в чате открывается чат с агентом этой доски. Доски листаются влево и вправо стрелками по
краям, колесом и перетаскиванием полосы. При открытии на полный экран вмещается примерно 2 доски,
при открытии на пол-экрана — примерно одна: ширина карточки считается от ширины контейнера через
`ResizeObserver`.

### 3. Доска

Бесконечное двумерное пространство: панорамирование колесом и перетаскиванием фона, зум по
`Ctrl`/`Cmd` + колесо. На доске располагаются артефакты — заметки, текст, фигуры, изображения,
сайты, консоли и CLI-приложения, блоки кода. Артефакты двигаются, меняют размер, редактируются по
двойному клику и соединяются стрелками. Заметки и текстовые артефакты показываются как markdown, а
по двойному клику открывается исходный текст. У выделенного артефакта появляются четыре точки-якоря,
перетаскивание с якоря на другой артефакт создаёт стрелку. У выделенной стрелки видны изгибы
(перетащить — сдвинуть, двойной клик — удалить) и полупрозрачные точки на серединах сегментов
(клик — добавить изгиб).

Стрелка всегда выходит из стороны артефакта под 90°: если прямая линия ушла бы вдоль края, к ней
добавляется короткий перпендикулярный вывод. Точка присоединения на стороне (порт) по умолчанию
распределяется автоматически между всеми стрелками, которые делят эту сторону, поэтому
параллельные связи не сливаются в одну линию. Порт можно и зафиксировать — в центре (`0.5`) или в
любой другой точке стороны (`0..1`).

Сверху доски — небольшая информация про доску: название (двойной клик — переименовать), счётчик
артефактов и связей, оценка качества раскладки (наведите на неё, чтобы увидеть разбор по причинам),
кнопки отката доски назад и вперёд, добавление артефакта, «вписать содержимое», выбор модели, на
которой агент работает с этой доской. Модель можно менять перед каждым запросом — как в шапке
доски, так и в шапке чата.

Изначально на досках ничего нет.

### 4. Агент

У агента есть набор инструментов.

**Восприятие**

| Инструмент | Что делает |
| --- | --- |
| `board_get_region` | Точные данные об артефактах и стрелках в заданной области |
| `board_get_schema` | Схематическое изображение области: ASCII-план или SVG |
| `board_screenshot` | Настоящий скриншот области доски |
| `board_check_intersections` | Детектор проблем раскладки + метрика качества и вердикт |
| `board_quality` | Только оценка: score, штраф, разбор по причинам, сравнение с прошлым замером |
| `board_route_arrows` | Ортогональный автороутер: прокладывает стрелки в обход артефактов |
| `board_clean_arrows` | Убирает мёртвые изгибы (усы, ступеньки, обрывки после сдвига блоков) |
| `board_arrange_graph` | Послойная раскладка графа: расставляет узлы так, чтобы стрелки не пересекались, и сразу их прокладывает |

`board_screenshot` работает через клиент: сервер шлёт в SSE-поток `screenshot_request`, браузер
растеризует нужную область доски и отправляет PNG обратно. Если клиент не ответил за отведённое
время, агент получает ASCII-схему — деградация предусмотрена, инструмент не падает.

**Расположение и содержание**

`artifact_create`, `artifact_update`, `artifact_move`, `artifact_delete`.

**Соединения**

`arrow_create` и `arrow_update` — с указанием, с какой стороны присоединять стрелку
(`top`/`right`/`bottom`/`left`/`auto`) и, если нужно, точки на этой стороне
(`fromOffset`/`toOffset`, `0.5` — строго центр; `-1` в `arrow_update` возвращает порт в
автоматический режим). Плюс ручная настройка изгибов: `arrow_bend_add`, `arrow_bend_move`,
`arrow_bend_remove`, `arrow_delete`.

**Маршрутизация**

`board_route_arrows` — серверный ортогональный автороутер. Строит по артефактам сетку Ханана,
ищет путь A\* с штрафами за повороты, за движение по уже занятому коридору и за пересечения,
поэтому стрелки обходят артефакты, редко гнутся и не ложатся друг на друга. Прокладывает
стрелки по очереди, поэтому пробует несколько порядков (создание, короткие первыми, длинные
первыми, сверху вниз) и оставляет раскладку с лучшей оценкой качества. Агент вызывает его
как обычный инструмент и может потом править результат теми же `arrow_bend_*`. Если узлы
накладываются или порт сидит внутри соседа, роутер не пишет маршрут: полилиния не изобретёт
коридор, которого нет. Если линия всё же вышла крюком, инструмент предупреждает — обычно
это неверные стороны присоединения или теснота, а не нехватка изгибов.

`board_clean_arrows` — выпрямляет мёртвые изгибы: торчащие усы на углах, короткие ступеньки
и обрывки линии, которые остаются, когда блок чуть сдвинули, а точки сгиба остались в старых
координатах. Не ищет новый путь — только приводит хранимую полилинию к тому, что уже рисуется.

**Раскладка графа**

`board_arrange_graph` — послойная раскладка (Sugiyama-подход) поверх уже созданных артефактов.
Разрывает циклы, раскладывает узлы по слоям вдоль потока, подбирает порядок внутри слоя
медианной эвристикой, выравнивает координаты и сразу прокладывает стрелки. Направление
`auto` сравнивает «слева направо» и «сверху вниз» по итоговой оценке качества и оставляет
лучший вариант. Узлы одной смысловой группы (`groups`) держатся рядом; `lockIds` удерживает
на месте то, что уже стояло на доске; `nodeIds` ограничивает раскладку своим графом.

Причина, по которой этот шаг вообще существует: замер на реальных досках показал, что
12 стрелок между 11 расставленными вручную узлами дают около 50 пересечений при **любых**
настройках автороутера. Пересечения определяются порядком узлов в слое, а не формой линий,
поэтому их нельзя вылечить маршрутизацией. Подробности — в
[docs/EXPERIMENTS.md](docs/EXPERIMENTS.md), запись A01.

**Скиллы**

`skill_list` и `skill_get` — плейбуки, которые агент подтягивает под задачу. Каталог (название и
«когда применять») всегда в системном промпте, полный текст приходит только по запросу.

**База знаний**

`kb_search`, `kb_add` — обе включаются и отключаются в настройках.

Каждый вызов инструмента — одна транзакция в истории доски, поэтому «откатить назад» отменяет
ровно один шаг агента. Упавший инструмент откатывается целиком и возвращает модели текст ошибки,
чтобы она могла исправиться, а не прерывает run.

### 5. Блок настроек

Открывается по кнопке «Настройки» и содержит несколько блоков:

- **Настройка провайдера LLM** — URL и key, модель по умолчанию, модель эмбеддингов. Ключ
  хранится на сервере и никогда не возвращается клиенту — только флаг «ключ задан».
- **Настройка системного промпта** — плюс лимит шагов с инструментами и температура; есть кнопка
  возврата промпта по умолчанию.
- **Скиллы** — простой редактор: список слева, справа название, «когда применять» и текст
  инструкции в markdown. Скиллы можно добавлять, выключать по одному, удалять и восстанавливать
  встроенные. Весь блок отключается одной галочкой.
- **Настройка простой базы знаний**, к которой у агентов есть доступ. Есть набор исходных записей,
  и агенты могут добавлять новые; функции добавления и доступа к базе опциональные и отключаются
  галочками. Поиск по базе семантический и векторный.

## Как агент раскладывает

Системный промпт намеренно тонкий: роль, координаты, несколько инвариантов и указание выбрать
скилл. Всё, что зависит от типа задачи, живёт в скиллах, а не в промпте.

**Скиллы.** Встроенных два. `artifact-set` — когда надо просто показать материал: ряды и сетка,
шаг 20px, воздух 40px. `graph-layout` — когда смысл в связях. Порядок в нём такой:
создать узлы, не мучаясь с координатами → создать **все** стрелки без указания сторон →
один вызов `board_arrange_graph` → точечные правки. Координаты узлов и стороны стрелок
считает раскладка: агент отвечает за смысл (какие узлы, какие связи, какие группы),
а не за геометрию. Пересечения решаются порядком узлов в слое, поэтому маршрутизацией
их вылечить нельзя — это измерено, см. [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md).

**Детектор** (`board_check_intersections`) находит: стрелки, режущие артефакты (с указанием
сторон входа и выхода), пересечения стрелок с углом пересечения и пометкой слишком пологих,
параллельные стрелки, слипшиеся в одну линию (с длиной слипшегося участка; задуманная развилка с
общим портом при этом не считается ошибкой), стрелки, идущие впритык к чужому артефакту,
наложения артефактов, слишком тесных соседей и подписи, которым не хватило места.

**Метрика качества** — взвешенный штраф, где стоимость проблемы соответствует тому, насколько она
мешает читать схему: наложение артефактов дороже слипшихся стрелок, слипшиеся дороже пересечений,
пересечения дороже лишних изгибов. Из штрафа считается `score` от 0 до 100. Метрика видна
пользователю в шапке доски и приходит агенту при каждой проверке вместе со сравнением с прошлым
замером, поэтому у него есть внятный критерий остановки: улучшения нет — прекращай.

## База знаний и векторная БД

Векторная БД написана с нуля и намеренно простая: плотные векторы в памяти, косинусная близость,
персистентность в JSON. Поиск гибридный — `0.65 × косинус + 0.35 × BM25`, поэтому и смысловые, и
точные словесные совпадения работают.

Эмбеддинги берутся у провайдера (`/v1/embeddings`), а если ключа нет или запрос упал — считаются
локально: хешированный мешок токенов и символьных триграмм на 384 измерения. Триграммы дают
устойчивость к русской морфологии. Каждый вектор помечен пространством, в котором посчитан, так
что при смене модели эмбеддингов база переиндексируется сама.

Исходные записи — про аниме и поп-культуру: Studio Ghibli, Evangelion, Cowboy Bebop, One Piece,
«Атака титанов», исекай, MAPPA, Trigger, киберпанк, Marvel, «Звёздные войны», покемоны, гача,
J-pop и city pop, мемы и другое.

## Модели

Список моделей подгружается из API DS Lab: `GET https://api.dslab.tech/v1/models`. API
OpenAI-совместимый, поэтому подойдёт и любой другой провайдер — достаточно поменять base URL.
Пока ключ не задан, показывается встроенный список моделей, чтобы интерфейс не был пустым.

## Архитектура

```
shared/   Доменные типы, геометрия стрелок и портов, детектор, роутер, раскладка, метрика
server/   Express + TypeScript, модули без взаимных зависимостей
  core/                 JsonStore, идентификаторы, ошибки
  modules/settings/     Провайдер, промпт, флаги базы знаний и скиллов
  modules/llm/          Клиент OpenAI-совместимого API, разбор SSE
  modules/boards/       Доски, история, операции над артефактами и стрелками
  modules/knowledge/    Векторная БД, эмбеддинги, гибридный поиск, сиды
  modules/skills/       Хранилище скиллов и два встроенных плейбука
  modules/chat/         История сообщений по доскам
  modules/agent/        Цикл агента, реестр инструментов, рендер схем, скриншоты
web/      React 19 + Vite + Zustand
  artifacts/            Реестр рендереров артефактов
  components/board/     Полоса досок, шапка, канвас, слой стрелок
  components/chat/      Сообщения, вызовы инструментов, композер
  components/settings/  Провайдер, промпт, скиллы, база знаний
bench/    Стенд экспериментов: пул задач, прогоны, рендер в PNG, наблюдательные метрики
```

Геометрия, детектор, роутер и метрика лежат в `shared/`, поэтому сервер и клиент считают одно и
то же: агент видит ту же оценку, что и пользователь в шапке доски.

Точки расширения ровно четыре, и каждая — одна запись в реестре:

- **новый тип артефакта** — `server/src/modules/boards/artifact.defaults.ts` (дефолты и подсказка
  для модели) плюс рендерер в `web/src/artifacts/renderers.tsx`;
- **новый инструмент агента** — файл в `server/src/modules/agent/tools/` и строка в `index.ts`;
- **новая методика раскладки** — скилл в настройках, код трогать не нужно;
- **другое хранилище** — один класс `JsonStore`.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

`npm run dev` поднимает сервер на `http://localhost:5174` и клиент на `http://localhost:5173`
(запросы `/api` проксируются на сервер). Откройте клиент, зайдите в «Настройки» → «Провайдер LLM»
и вставьте ключ DS Lab — после этого подтянется живой список моделей.

Продакшн-сборка:

```bash
npm run build   # собирает клиент в web/dist
npm start       # сервер отдаёт и API, и собранный клиент на :5174
```

Данные лежат в `data/` рядом с проектом: `boards.json`, `chats.json`, `knowledge.json`,
`settings.json`. Удалить папку — вернуться к чистому состоянию.

## Тесты

```bash
npm test         # сервер + клиент
npm run typecheck
```

Сервер (Vitest + Supertest): операции над доской и история, гибридный поиск и переиндексация,
ASCII- и SVG-рендер области, валидация аргументов инструментов, автороутер и метрика как
инструменты агента, скиллы (сиды, CRUD, каталог в промпте, отключение), цикл агента на
замоканном провайдере — включая ошибку инструмента, лимит шагов, скриншот с ответом клиента и без
него — и HTTP-слой вместе с потоковым `text/event-stream`.

Клиент (Vitest + Testing Library): геометрия якорей, портов и перпендикулярных выходов, детектор
всех видов конфликтов, ортогональный роутер, метрика качества, реестр артефактов и инлайн-
редактирование, композер, отрисовка вызовов инструментов, сборка стримингового ответа в сторе,
редактор скиллов и оценка качества в шапке доски.

## Стенд экспериментов `bench/`

Отдельный стенд, чтобы улучшения движка раскладки можно было мерить, а не обсуждать.
Порядок работы — [docs/IMPROVEMENT_LOOP.md](docs/IMPROVEMENT_LOOP.md).

```bash
# сервер стенда на отдельной data-директории — боевые доски не трогаются
TECA_DATA_DIR=./bench/data PORT=5199 node_modules/.bin/tsx server/src/index.ts

# прогон пула задач: по умолчанию только дешёвые модели, параллельность не больше 2
node_modules/.bin/tsx bench/run.ts --exp=E02 --task=all --model=deepseek-v4-flash --concurrency=2

# дорогая модель — только явным флагом, и точечно: одна доска на ней ≈ $1.6
node_modules/.bin/tsx bench/run.ts --exp=E02x --task=wiki-anime --model=claude-sonnet-5 --allow-expensive

# сводные таблицы
node_modules/.bin/tsx bench/report.ts --exp=E01,E02

# офлайн-эксперименты на сохранённых досках — без API и полностью воспроизводимо
node_modules/.bin/tsx bench/summary.ts        # что даёт раскладка на реальных досках
node_modules/.bin/tsx bench/offline.ts        # свипы параметров роутера
node_modules/.bin/tsx bench/gate-sim.ts       # сколько вызовов отвергают гейты
node_modules/.bin/tsx bench/snapshot.ts       # отрендерить все доски в PNG
```

Пул задач в `bench/tasks.ts` заморожен: задачи не редактируются, новые добавляются
с новым id, иначе сравнение с прошлыми прогонами теряет смысл. Каждый прогон пишет
JSON с полной телеметрией и PNG результата в `bench/out/<эксперимент>/`.


**Деньги.** Шлюз резервирует по `prompt + max_tokens`, а не списывает по факту, и резерв
держится против всего баланса — один параллельный прогон дорогой модели блокирует и дешёвые.
Поэтому стенд по умолчанию гоняет только дешёвые модели, параллельность ограничена двумя
потоками (с дорогой моделью — одним), а прогон не стартует, если оценка резерва выше
`--budget-run` (на доску, по умолчанию 25 единиц) и `--budget-exp` (на эксперимент, 400).
Единица шлюза — не доллар: по его собственным оценкам выходит около 65 единиц на доллар,
то есть полный пул из 8 задач на `deepseek-v4-flash` стоит примерно $0.30, а на
`claude-sonnet-5` — примерно $13. Фактический расход виден в `usage`
каждого результата и в чипе токенов в шапке ответа агента.
Промпт и скиллы хранятся в `data/`, поэтому правка кода не доходит до работающей
установки сама. Обновить: кнопки «Вернуть промпт по умолчанию» и «Восстановить
встроенные» в настройках, либо `node_modules/.bin/tsx bench/sync-prompt.ts data`.
